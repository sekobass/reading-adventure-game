# 謎解きダンジョン ～失われた秘宝～

小学5年生を主な対象とした、文章読解型の2DアクションRPGです。村人の話、日記、石碑を読み、探索や戦闘で分かったことを試します。宝箱から遺跡の番人まで全5ステージ。各ステージに読解レベル5段階と、レベルごとに2種類の問題があります。

## 起動

公開サイトではブラウザでページを開くだけで遊べます。ローカルで試す場合は、リポジトリのルートで以下を実行し、ブラウザで `http://localhost:8000/` を開いてください。

```sh
python -m http.server 8000
```

ゲームは静的ファイルのみで動作します。依存パッケージ、外部API、ゲーム用バックエンドは不要です。ローカルでは、ブラウザが問題JSONを読み込めるようHTTPで配信してください。

## 操作

| キーボード | 操作 |
| --- | --- |
| 矢印 / WASD | 移動 |
| Space | 剣で攻撃（長押しで連続攻撃） |
| E | 人に話す、物を調べる、品物を拾う |
| Q | 選んだ魔法または回復薬を使う |
| 1 / 2 / 3 | 炎 / 氷 / 回復薬を選ぶ |
| R | ミッションと、取得済みの文章を読む |
| Esc | 一時停止、または開いている画面を閉じる |

タブレットでは左下のジョイスティックで移動し、右下のボタンで攻撃、魔法・道具の使用、調査、切り替えができます。移動と攻撃は同時に操作できます。ゲーム枠上部に文章の再確認、一時停止、メニューがあります。横向き推奨です。設定の「タッチ操作」で自動表示・常時表示・非表示を選べます。

文章やメニューを開いている間はゲームが停止します。文章の文字サイズを18～26pxで調整できます。読解の難易度は次に始めるステージから変わり、戦闘の難易度とは別に設定できます。

## セーブと学習履歴

ステージ解放、クリア状況、レベル、経験値、ゴールド、装備、回復薬、設定は自動保存します。再訪時は「冒険をつづける」からステージを選べます。挑戦中にリロードした場合は、ステージ入口から新しい挑戦を始めます。依頼の品など、ステージ内だけで使う道具は挑戦ごとの所持品です。

上部の「学習履歴」から、プレイ履歴、読解での誤答なしにクリアした割合、問題分類・レベル別の初回成功率、ヒント使用率を確認できます。未クリアの挑戦も集計に含めます。文章表示時間は記録し、成功判定には使用しません。CSVはUTF-8（BOM付き）です。保存先は同じブラウザ・サイトの `localStorage` です。ゲームの初期化と履歴削除にはそれぞれ確認画面があります。

## 問題データの編集

- `data/stages.json` はステージ名、背景、開始座標、障害物、水域と橋の見た目を定義します。座標は480×288のゲーム座標です。
- `data/questions.json` の1要素が1問です。一意の `id`、`stageId`、`difficulty`（1～5）、`type`、`mission`、段階別の `hints`、クリア後の `explanation` を指定します。各ステージ・レベルの組に最低1問を定義してください。複数ある場合は再挑戦で切り替わります。
- `objects` に配置する人や物を定義します。`text` を持つ物は読めます。`delivery: true` を付けた人物には、現地で依頼の品を届けられます。
- `rules` の `target` に物のIDを指定します。`when` は所持数 `{ "item": "燃料", "count": 1 }` やフラグ `{ "flag": "aligned" }` などの条件です。`then` には `give`、`take`、`set`、`open`、`spawn`、`move`、`win` を指定できます。`wrong` は誤答時の行動名です。条件判定があるルールでは条件不成立時に、無条件ルールでは処理と同時に記録されます。
- `sequence` で操作できる台座、正しい順序、完成時のフラグを定義できます。`completeWhen` は複数の依頼などを組み合わせたクリア条件です。`enemies` や `spawn` で、番人の弱点（`fire` または `ice`）、停止時間、撃破時クリアを指定できます。
- 既存の操作を使う新しい文章問題はデータの追加で作れます。文章・配置・正誤条件・ヒント・解説を一緒に更新し、到達可能性と誤答後に続けられることを確認してください。

## GitHub Pages とオフラインプレイ

GitHub の **Settings → Pages** で **Deploy from a branch** を選択し、ゲームを含むブランチの **/(root)** を指定します。公開されたリポジトリのサブパスでも相対参照で動作します。

HTTPS の公開ページを一度オンラインで開き、読み込みが完了すると Service Worker が必要なファイルを保存します。対応環境では、Chrome のインストールメニューや iPad Safari の共有メニューからホーム画面に追加できます。更新を配信する場合は `sw.js` のキャッシュ名の版を上げます。旧版のタブをすべて閉じると新しいキャッシュが有効になります。

## 実装状況とテスト

- 実装済み。5ステージ、50問、移動と衝突判定、戦闘とボス、魔法と回復、経験値と装備強化、ミッション、段階ヒント、自動保存、学習履歴とCSV、タッチ操作、PWA、オフラインプレイ。
- 未実装。挑戦途中の位置・HP・仕掛け状態の保存、端末間の進行同期。イラストと効果音はコードで描画・生成し、外部素材への依存はありません。

### Ver.0.1.1 の修正とブラウザテスト

渡船直後などにクリア画面を閉じても、画面上部の「クリア結果」または E／「調べる」で再表示できます。PWA はクエリパラメータ付きのURLでもキャッシュを利用し、ゲーム用ファイルがキャッシュにもネットワークにもない場合は HTTP 503 を返します。以前のセーブと学習履歴は引き続き利用できます。

ブラウザ統合テストでは、キーボードとタッチで燃料を拾って船を動かし、クリア画面を再表示してステージ3へ進みます。旧キャッシュからの切り替え、通信切断、クエリパラメータ付きのオフライン起動も確認できます。

```sh
npm ci
npx playwright install chromium
npm test
npm run test:browser
```

インストール済みの Chromium を使う場合は、環境変数 `CHROMIUM_EXECUTABLE` に実行ファイルのパスを指定できます。Playwright はテスト用の依存関係です。
