# 謎解きダンジョン ～失われた秘宝～

小学5～6年生を主な対象とした、文章読解型の2DアクションRPGです。村人の話、日記、石碑を読み、探索や戦闘で分かったことを試します。宝箱から遺跡の番人まで全5ステージ。各ステージに読解レベル5段階と、レベルごとに2種類の問題があります。

## Ver.1.0 開発版「失われた王国 ～七つの封印～」

ローカルでは `http://localhost:8000/kingdom/`、GitHub Pagesではリポジトリの公開URLに `kingdom/` を付けると起動できます。従来のルートURLはVer.0.2です。新版のフッターから旧版へ戻れます。新版は独立した保存キーとService Workerのスコープを使います。

### 遊べる範囲

| 章 | ミッション | 読解 |
| --- | --- | --- |
| 1 消えた村人 | 水車小屋の足跡、鐘番の隠れ部屋 | 発言の時刻・対象・訓練記録を照合する |
| 2 裏切り者のいる村 | 見張りのアリバイ、偽印の取引 | 場所と通行記録の矛盾を見つける |
| 3 呪われた森林 | 霧の道しるべ、根の下の封印 | 例外条件と過去の章の証拠を組み合わせる |

各ミッションは異なる証言・攻略条件を持つ2種類、計12問です。データは現在Lv.3向けです。読解の設定は5段階で、配信データの中から設定に近いレベルを選びます。戦闘難易度は独立しています。第2章末に取引記録を公開するか証人を守るかで、第3章の初回出題、報酬、終幕の文章が変わります。

作戦卓では、計画と理由を選び、裏付けとなる証拠を組み合わせて提出します。その後で、探索や仕掛けを実行します。誤答で増援が出現し、規定回数に達すると次の資料で再挑戦できます。読む時間に制限はありません。

操作は旧版と同じです。新版では G またはタッチの「強攻撃」、H または「回復魔法」を追加しました。強攻撃・防御・回避は気力を、回復魔法はMPを消費します。3体のボスがそれぞれ3段階で攻撃パターンと弱点を変えます。周辺地図、ダメージ表示、オン・オフを選べるBGM、護符・回復薬の購入にも対応しています。

### 新版の問題作成と公開

1. 新版の「問題管理」で公開版の問題を選び、「問題を追加」または「複製」でひな型を作ります。実例は `kingdom/data/questions.json` です。
2. 問題ID、ミッション、読解レベル、各証言の本文、計画と理由、ヒント、解説を編集します。「計画の場所・資料と正解証拠（JSON）」の `sources` に現地で読む資料のID、`evidence` に結論を裏付けるもののIDを指定します。既存の配置・`rules`・`enemies`・`sequence` の形式も使用します。
3. 生成AIで用意する場合は、既存問題1件をサンプルに同じフィールドを出力させます。問題IDが重複しないよう確認し、取り込み画面に公開分を含む配列のJSONを指定します。CSVも読み書きでき、複合列はセル内JSONを維持します。
4. 「入力をチェック」で参照先、証拠、到達可能性、進行条件を確認します。文章が正解を裏付けているかや戦闘の難しさは、通常の進行・学習履歴から分離された「テストプレイ」で確認します。
5. JSONを書き出し、`kingdom/data/questions.json` を差し替えてPRで確認します。**同じデータ形式で問題だけを更新する場合**、ゲーム本体の変更は不要です。オンライン起動時に検証済みデータを取得し、オフラインでは最後に取得できた版か同梱データを使います。コードや配信形式を変える場合は、`kingdom/sw.js` のキャッシュ版も更新します。

新版の設定から、進行と学習履歴をまとめたJSONバックアップを書き出し、内容を確認してから復元できます。旧版の保存領域はそのまま利用できます。

### 今回の実装範囲と残作業

これはVer.1.0に向けた開発版です。第4〜10章、残り6つの封印、最終章のマルチエンディング、読解レベルごとの独立した150問規模の問題集は今後の実装対象です。広域マップ、隠し通路・移動床、本格的なサブミッション、スキルツリー、魔法の習得、学習成績の推移表示も未実装です。

`npm test` は旧版の回帰テストと新版の全12問を実行します。`npm run test:browser` はキーボード・タッチ、問題管理、版を分けた保存、オフライン起動を検証します。

## 起動

公開サイトではブラウザでページを開くだけで遊べます。ローカルで試す場合は、リポジトリのルートで以下を実行し、ブラウザで `http://localhost:8000/` を開いてください。

```sh
python -m http.server 8000
```

ゲームは静的ファイルのみで動作します。依存パッケージ、外部API、ゲーム用バックエンドは不要です。ローカルでは、ブラウザが問題JSONを読み込めるようHTTPで配信してください。

## 操作

| キーボード | 操作 |
| --- | --- |
| 矢印 / WASD | 移動 |
| Space | 剣で攻撃（長押しで連続攻撃） |
| E | 人に話す、物を調べる、品物を拾う |
| Q | 選んだ魔法または回復薬を使う |
| 1 / 2 / 3 / 4 | 炎 / 氷 / 回復薬 / 雷を選ぶ |
| F | 一時防御（移動はゆっくり） |
| Shift | 向いている方向に短く回避 |
| R | ミッションと、取得済みの文章を読む |
| Esc | 一時停止、または開いている画面を閉じる |

タブレットでは左下のジョイスティックで移動し、右下のボタンで攻撃、防御、回避、魔法・道具の使用、調査、切り替えができます。移動と攻撃は同時に操作できます。ゲーム枠上部に文章の再確認、一時停止、メニューがあります。横向き推奨です。設定の「タッチ操作」で自動表示・常時表示・非表示を選べます。

文章やメニューを開いている間はゲームが停止します。文章の文字サイズを18～26pxで調整できます。読解の難易度は次に始めるステージから変わり、戦闘の難易度とは別に設定できます。

## 攻略計画と戦闘

各地の文章を集めてから、現地の計画を調べます。表示順が変わる4つの案の中から、条件をすべて満たす案を選び、マップ上で実行します。読解Lv.4以上は、計画に加えて根拠も選びます。計画を2回間違えた挑戦は保留になり、ヒントを見て別の記録で再挑戦できます。

| ステージ | 読解と実行 |
| --- | --- |
| 1 宝箱の秘密 | 証言の順番と箱が置かれた位置を区別し、空と罠の箱を除外する |
| 2 川を渡る方法 | 川の今日の状況と積み荷の用途を照合し、燃料を取ってから乗船する |
| 3 魔物の弱点 | 2つの記録から番人の前半・後半の条件を区別し、氷と剣、防御・回避を使う |
| 4 村人の依頼 | 二人の用途・数量・鮮度・受け渡し順を照合する |
| 5 古代遺跡の謎 | 石碑から台座の順を導き、別の記録から守り手と番人の戦闘順・弱点の変化を判断する |

向いている方向に魔法を放ちます。炎は燃焼、氷は凍結、雷は麻痺を起こします。敵の耐性や戦況によって効き方が変わります。剣・魔法・敵の攻撃は壁に遮られます。MPは時間で回復します。ボス戦の広間は戦闘中に閉鎖され、勝利で開放されます。敗北時は入口から再挑戦できます。

## セーブと学習履歴

ステージ解放、クリア状況、レベル、経験値、ゴールド、装備、回復薬、設定は自動保存します。再訪時は「冒険をつづける」からステージを選べます。挑戦中にリロードした場合は、ステージ入口から新しい挑戦を始めます。依頼の品など、ステージ内だけで使う道具は挑戦ごとの所持品です。

上部の「学習履歴」から、プレイ履歴、読解での誤答なしにクリアした割合、問題分類・レベル別の初回成功率、ヒント使用率を確認できます。未クリアの挑戦も集計に含めます。文章表示時間は記録し、成功判定には使用しません。CSVはUTF-8（BOM付き）です。保存先は同じブラウザ・サイトの `localStorage` です。ゲームの初期化と履歴削除にはそれぞれ確認画面があります。

## 保護者向けの問題管理と公開

1. 上部の「問題管理」で既存の問題を選び、「問題を追加」または「複製」で下書きを作ります。追加は公開版の同じステージ・難易度をひな型にします。
2. ステージ、難易度、問題文、選択肢と正解、根拠、ヒント、解説、台座の順序、ボスの弱点を編集できます。品物の所持数やフラグなどの実行条件、地図上の座標や敵の配置は「配置・正解条件・敵の詳細（JSON）」を開いて編集します。
3. 「入力をチェック」でIDや正解数、条件の矛盾、壁を含めた到達可能性、問題を完了できる手順を確認します。「テストプレイ」では編集中の問題をそのまま遊べます。文章がどのように読まれるか、戦闘のタイミングが適切かは実際に試してください。
4. 「下書きを保存」でこのブラウザに保存します。下書き、テストプレイ、問題の削除や置換は、通常プレイの進行・学習履歴に影響しません。問題のIDを変更すると、変更前の履歴には以前のIDが残ります。
5. 「JSONを書き出す」で、共有用の問題一覧を作ります。Excelで編集する場合は「Excel用CSVを書き出す」を使い、UTF-8で保存してください。座標・条件・敵などの複合項目は、セル内のJSON形式を維持します。読み込み後に置換を押すと、現在の下書き全体が入れ替わります。

全端末の通常プレイへ配布するには、書き出したJSONでGitHubリポジトリの **data/questions.json** を置き換えます。公開版の新旧が混ざらないよう **sw.js** のキャッシュ版も上げ、PRで内容とテスト結果を確認してから Pages の配信ブランチにマージします。公開後はゲームのタブをすべて閉じて開き直すと、新版のキャッシュが有効になります。ゲーム内の管理画面はリポジトリへの書き込みや公開を行いません。

## 問題データの編集

- `data/stages.json` はステージ名、背景、開始座標、障害物、水域と橋の見た目を定義します。座標は480×288のゲーム座標です。
- `data/questions.json` の1要素が1問です。一意の `id`、`stageId`、`difficulty`（1～5）、`type`、`mission`、段階別の `hints`、クリア後の `explanation` を指定します。各ステージ・レベルの組に最低1問を定義してください。複数ある場合は再挑戦で切り替わります。
- `objects` に配置する人や物を定義します。`text` を持つ物は読めます。`delivery: true` を付けた人物には、現地で依頼の品を届けられます。
- `rules` の `target` に物のIDを指定します。`when` は所持数 `{ "item": "燃料", "count": 1 }` やフラグ `{ "flag": "aligned" }` などの条件です。`then` には `give`、`take`、`set`、`open`、`spawn`、`move`、`win` を指定できます。`wrong` は誤答時の行動名です。条件判定があるルールでは条件不成立時に、無条件ルールでは処理と同時に記録されます。
- `plan` で計画を開く物のID、参照する記録のID、4つの案と正解を定義します。
- `sequence` で操作できる台座、正しい順序、完成時のフラグを定義できます。`completeWhen` は複数の依頼などを組み合わせたクリア条件です。`enemies` や `spawn` で、番人の段階別の属性・攻撃パターン・防御条件と、撃破時クリアを指定できます。
- 既存の操作を使う新しい文章問題はデータの追加で作れます。文章・配置・正誤条件・ヒント・解説を一緒に更新し、到達可能性と誤答後に続けられることを確認してください。

## GitHub Pages とオフラインプレイ

GitHub の **Settings → Pages** で **Deploy from a branch** を選択し、ゲームを含むブランチの **/(root)** を指定します。公開されたリポジトリのサブパスでも相対参照で動作します。

HTTPS の公開ページを一度オンラインで開き、読み込みが完了すると Service Worker が必要なファイルを保存します。対応環境では、Chrome のインストールメニューや iPad Safari の共有メニューからホーム画面に追加できます。更新を配信する場合は `sw.js` のキャッシュ名の版を上げます。旧版のタブをすべて閉じると新しいキャッシュが有効になります。

### ブラウザテスト

渡船直後などにクリア画面を閉じても、画面上部の「クリア結果」または E／「調べる」で再表示できます。PWA はクエリパラメータ付きのURLでもキャッシュを利用し、ゲーム用ファイルがキャッシュにもネットワークにもない場合は HTTP 503 を返します。以前のセーブと学習履歴は引き続き利用できます。

ブラウザ統合テストでは、キーボードとタッチで燃料を拾って船を動かし、クリア画面を再表示してステージ3へ進みます。旧キャッシュからの切り替え、通信切断、クエリパラメータ付きのオフライン起動も確認できます。

```sh
npm ci
npx playwright install chromium
npm test
npm run test:browser
```

インストール済みの Chromium を使う場合は、環境変数 `CHROMIUM_EXECUTABLE` に実行ファイルのパスを指定できます。Playwright はテスト用の依存関係です。
